**Project:** @Orlumi Studio → @Petal Nook

## Purpose

The approved BgRoom will determine the final visual perspective and exact furniture placement. Until that art is locked, room coordinates must not be scattered across scenes and scripts.

M7.1 introduces one layout source of truth:

`game/data/room_layout.gd`

When the approved background arrives, final tuning happens in that file rather than by repeatedly editing gameplay code.

## Runtime integration

`MainRoom` now applies furniture rectangles and Lumie movement bounds from `room_layout.gd` during `_ready()`.

The `.tscn` coordinates remain useful editor fallbacks, but runtime layout source of truth is the centralized config.

This prevents approved-art calibration from affecting:

- economy
- purchase logic
- save data
- offline rewards
- Lumie state machine
- Photo Mode

## Debug calibration overlay

A dedicated overlay is available at:

`game/scenes/debug/layout_calibration_overlay.tscn`

It shows:

- HUD safe zone
- right UI safe zone
- active floor
- Area 2 reserve
- Lumie movement region
- each furniture rectangle and centre anchor

The overlay is hidden by default.

For a Godot debug run, launch the game with:

`--layout-debug`

The overlay must never be exposed as normal player UI.

## Final BgRoom calibration procedure

After approved `bg_room_main.png` is placed into production:

1. run asset-contract CI;
2. boot MainRoom with `--layout-debug`;
3. inspect background crop against 1080 × 1920;
4. adjust safe zones in `room_layout.gd` if needed;
5. calibrate Little Pot first;
6. calibrate Lumie movement bounds;
7. calibrate Curtain / Wooden Rack / Small Table;
8. verify Area 2 remains visually reserved;
9. rerun Godot CI;
10. lock the layout revision before approved furniture art integration.

## Next gate
